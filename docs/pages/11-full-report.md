# Page 11 - Full report

## Purpose
Render the long-form analytical report (`REPORT.md`) inline so users can review the full executive summary, EDA tables, recommendations and Action Dashboard without leaving the app. Also provides the launch point for the **PDF report builder** (separate route at `/report`).

Primary user: senior management consuming the analysis; anyone wanting to print/PDF-export the full report.

## Layout map

This tab is a single full-width card with two parts:

```
+-----------------------------------------------------------------------------+
| Action bar (sticky, hidden on print)                                       |
|   File icon + title + "Download .md" + "Print / Save PDF" buttons          |
+-----------------------------------------------------------------------------+
| Rendered markdown body (full REPORT.md content)                            |
|   Headings, tables, lists, blockquotes - all custom-styled JCB palette.    |
+-----------------------------------------------------------------------------+
```

Plus the separate dedicated route at `/report`:

```
+-----------------------------------------------------------------------------+
| /report (top nav link)                                                      |
|   Step 1: pick a date range (calendar + quick-pick chips)                  |
|   Step 2: "Generate report" -> fires ~25 endpoints with the range          |
|   Renders sections 1-12 inline + Print/Save-PDF button                     |
+-----------------------------------------------------------------------------+
```

## Widget catalogue (Full report tab)

### Markdown renderer
- **Source**: `GET /api/report` returns the raw `REPORT.md` text/markdown.
- **Implementation**: a small trusted markdown -> HTML renderer in [frontend/src/lib/markdown.ts](../../frontend/src/lib/markdown.ts). Handles headings (h1-h4), paragraphs, ul/ol lists, code spans, bold/italic, blockquotes, hr, tables, autolinks. Not a general-purpose renderer - safe because the source is our own generated REPORT.md, not user input.
- **Styling**: `.wty-md` class adds JCB-themed CSS (yellow headings, yellow code, hover-on-row tables, blockquote left-border accent).
- **Print styles**: when the user clicks Print/PDF, light-theme overrides kick in (white bg, dark text, JCB yellow kept as accent) plus `break-inside-avoid` on every section.

### Download .md button
- Direct link to `GET /api/report` with a `download="WTY-REPORT.md"` attribute.

### Print / Save PDF button
- Calls `window.print()`. The print CSS in [frontend/src/index.css](../../frontend/src/index.css) hides the nav, footer and the sticky action bar, switches the body to white, and styles for A4 with 10-14 mm margins. The browser's "Save as PDF" destination produces a clean PDF.

## Widget catalogue (`/report` page)

### Step 1: Range picker
- Calendar inputs (`From / To`) showing the actual data window as a hint.
- Quick-pick chips: All / Last 30d / 90d / YTD / 2024 / 2025 / Pre-regime / Post-regime.
- "Generate report" button.

### Step 2: Report body
After "Generate report" is clicked, the page fires ~25 endpoints in parallel with the chosen window, then renders 12 sections:

1. Headline KPIs (8 tiles)
2. Auto-generated headlines (from `/headlines`)
3. Temporal trends (monthly + YoY)
4. Vetting regime impact (table + monthly stacked bar)
5. Pareto & root-cause (area Pareto + model league + top 25 parts)
6. Build-date cohort (DOA area chart)
7. Operations (Cannot-Detect / ASD / seasonality)
8. Vetter scorecard
9. People & Places (recidivism / dealers / customers / countries)
10. Supply chain (top 20 suppliers)
11. NLP (top tags + bigrams)
12. Data quality (anomaly tiles)
13. Footer notes + limitations

A sticky action bar at the top shows `loading N/25` while queries are in-flight. Print is disabled until everything has finished loading.

### Print / Save PDF
Same browser-print flow as the Full report tab, but with full filter coverage (each section runs against the chosen date range).

## Cross-filter behaviour
- The **Full report tab** ignores global filters - it always shows the full `REPORT.md` content.
- The **`/report` page** uses **only the date range** picked in its own UI - it does not inherit the dashboard's filter bar (intentional, to keep the report standalone and shareable).

## Common interpretations
1. The Full report tab is the right place to read the executive summary and recommendations exactly as the analyst wrote them.
2. Use the `/report` page when you need a printable, date-bounded snapshot for a stakeholder.
3. Both routes route to the browser print dialog, which natively supports "Save as PDF" - no extra dependencies required.

## Known limitations
- `REPORT.md` is regenerated by `scripts/report.py` from the raw CSV. To refresh, re-run `python scripts/report.py`. The Full report tab will pick up the new file on the next reload.
- The `/report` page is **not** server-side rendered - it relies on client-side endpoint calls + browser print. For true one-click server-side PDF, see IMPROVEMENTS.md (would require Puppeteer / Chromium dep).
- Print CSS targets A4 with 10-14 mm margins; if you need US Letter or different margins, edit `@page` in [frontend/src/index.css](../../frontend/src/index.css).
- Print chart fidelity depends on browser rendering - Edge / Chrome are excellent; Firefox PDF export sometimes drops Recharts SVGs.
